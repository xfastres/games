# 开发计划

按阶段做。没有完成当前阶段的验收之前，不开始下一个阶段的系统。

工期按里程碑看，不把各阶段天数加起来当成承诺。

## 阶段 0：项目审计与技术验证

目标：确认工具链，跑通最小场景。不实现战斗、经济、探索、肉鸽和模组扫描。

任务：

1. 检查目录、Godot 版本、现有文件和 Git。
2. 复用已有的 `AGENTS.md`，不覆盖无关内容。
3. 写设计、架构、数据、模组和开发计划文档。
4. 建立可运行的 Godot 4 项目。
5. 技术验证场景：网格、临时领主移动、按配置放置建筑、拒绝非法放置和无效配置。
6. 用当前 Godot 版本做脚本检查、自动化场景测试和实际启动。

验收：

- 空白网格上可以移动临时领主。
- 可以把测试建筑放在合法格子上，场景实例来自配置里的 `scene`。
- 占用格和网格外点击会显示明确错误。
- 无效配置会被拒绝，并说明原因。
- 合法配置仍然能加载。

禁止：在网格、实例化和 JSON 校验还没跑通时生成全部游戏内容。

## 阶段 1：战斗原型

地图和网格建造、城墙、弓箭塔、敌人、投射物、受伤和死亡、金币奖励、城堡生命、失败和重新开始。

验收：可以独立打完一次防守。失败条件可靠。敌人不会无故穿墙或永远卡住。

## 阶段 2：经济与建造

农场、伐木场、住宅、工坊，四种资源，生产、造价、升级，昼夜阶段，合法建造和拆除返还。

验收：生产和建造形成闭环。资源不会凭空增加，也不会出现负数。

## 阶段 3：领主探索与扩张

领主移动、攻击和生命，迷雾与区域，资源点、营地、遗迹，清理区域、前哨和开采，返城后再夜战。

验收：不扩张也能做基础建设；探索能带来新的资源和建造空间。

## 阶段 4：肉鸽与首领战

3 选 1，至少 15 个数据驱动强化，3 种普通敌人和 1 个首领，8 夜难度，胜利、失败和局外解锁。

验收：连续两局能得到不同强化组合。首领战能正常结束。

## 阶段 5：内容注册与本地模组

领主、建筑、敌人和强化的注册表，唯一 id、版本和依赖检查，本地内容包扫描，示例包，错误日志和加载报告。

验收：放入示例包并重启后，可以选择新领主或建造新建筑。错误内容被拒绝，基础游戏仍能启动。

## 阶段 6：可玩版本打磨

主菜单、设置、暂停、存档，数值调整，基础动画、音效和反馈，完整流程测试，Windows 导出包。

验收：从主菜单玩完一局。重启后约定的存档还在。没有阻断游戏的错误。
