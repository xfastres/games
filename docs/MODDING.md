# 模组与本地内容包

第一版只做数据和素材模组。不执行玩家提供的 GDScript，也不做在线工坊。

阶段 0 不会扫描 `mods/`。把文件放进这个目录不会改变游戏。加载器目前只读取明确传入的 `res://` 配置。

## 三个阶段

### 阶段 A：本地内容包

第一版目标。玩家把内容包放到受控目录，用 JSON、图片和音频增加领主、建筑、敌人和强化，并且只能使用游戏已经实现的行为类型。

### 阶段 B：完整内容包

后续版本。增加自定义地图、波次、升级树、事件和更多可组合行为。提供示例模板。

### 阶段 C：玩家工坊

更后面的版本。导入导出、依赖管理、内容预览，以及平台上的发布和订阅。发布平台确定后再选 Steam Workshop 或对应方案。

## 目标目录

下面是阶段 A 的目标形状，不是阶段 0 已实现的加载结果。

```
mods/frost_lord_pack/
├── mod.json
├── lords/frost_lord.json
├── buildings/frost_tower.json
├── upgrades/frost_upgrades.json
└── assets/
```

`mod.json` 的目标字段包括：

- `id`：全局唯一的内容包 id
- `name`
- `version`
- `game_api_version`：本游戏模组 API，不是 Godot 版本
- `dependencies`
- `content`：各类 JSON 的相对路径

## 必须遵守的规则

- 内容对象 id 全局唯一。重复 id 报错，不能静默覆盖。
- 内容包声明自己兼容的 `game_api_version`。
- 加载前校验格式、依赖和资源路径。
- 外部路径只能落在该内容包目录和游戏允许的资源目录内。不能读取任意用户文件。
- 无效 JSON、丢失素材、未知行为类型要给出明确错误。
- 某个内容包加载失败时，基础游戏和主菜单仍然要能启动。阶段 0 还没有主菜单；技术验证场景在合法配置可加载时会显示非法样本的拒绝原因，不会因此退出。
- 模组不能替换核心脚本、场景工程或 `project.godot`。
- 以后的存档要记录内容包 id、版本和内容引用，并能发现缺失内容或不兼容版本。
- 不执行内容包里的任意脚本。

内置的 `data/` 和外部内容包以后走同一套校验后的定义对象。阶段 0 只有内置建筑文件这一条路径。
