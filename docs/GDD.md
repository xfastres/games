# 边境守望（Frontier Wardens）游戏设计

阶段 0 只记录已经确定的设计方向。这里写的是目标，不是已经做好的功能。当前可运行内容只有技术验证场景，见 `docs/DEVELOPMENT_PLAN.md`。

## 游戏概述

单人 PC 游戏。玩家白天建设、生产和探索，夜晚守住城堡。每局通过随机强化形成不同打法。内容以后要能继续增加领主、建筑、敌人、地图、遗物和本地内容包。

- 引擎：Godot 4 + GDScript
- 视角：2D 斜俯视
- 地图：网格建造
- 单局目标时长：约 15–25 分钟
- 第一版美术：占位图形，先验证循环

参考体验来自 Thronefall、Crown of Greed、Age of Respair 这一类「经营 + 防守」游戏，但不复制它们的内容。

## 核心循环

1. 新游戏，选择领主。
2. 白天：建造、生产，并控制领主探索迷雾。
3. 发现资源点、遗迹或敌人营地，决定占领、开发或放弃。
4. 结束白天，进入夜战。
5. 抵御敌人，保护核心城堡。
6. 城堡被摧毁则失败，并进入局外成长结算。
7. 城堡存活则结算资源，获得 3 选 1 的肉鸽强化。
8. 未到最终夜则进入下一轮白天；完成最终夜则胜利，并解锁少量局外内容。

## 四个系统

### 塔防战斗

敌人攻击城墙并寻找突破口。后续可以有飞越城墙或破坏防御设施的特殊敌人。第一版先保证普通敌人的移动、攻击、受伤、死亡，以及城堡失败判定可靠。

### 领主探索

玩家直接控制领主走进迷雾，发现森林、矿脉、遗迹和敌人营地。探索要改变领地能开发的空间和资源，而不是只增加一条行走动画。

### 领地经营

农田、伐木场、住宅、工坊和防御设施争夺土地、人口和资源。建造、升级、拆除和生产必须有明确的资源变化，不能凭空增减。

### 肉鸽成长与模组

每夜胜利后从随机强化里 3 选 1。领主、建筑、敌人和强化都通过内容定义注册。第一版只做本地数据与素材内容包，不执行玩家脚本，也不做在线工坊。

## 第一版要做

| 模块 | 目标 |
| --- | --- |
| 地图 | 一张固定地图，网格建造，迷雾探索 |
| 领主 | 1 个可操作领主：移动、攻击、技能、生命值 |
| 建筑 | 约 6 种基础建筑，可建造、选中、升级、拆除 |
| 资源 | 金币、木材、粮食、石料 |
| 探索 | 6–8 个外围区域，含资源点、遗迹、敌人营地 |
| 敌人 | 3 种普通敌人 + 1 个最终首领 |
| 防守 | 城墙、弓箭塔、寻路、波次、城堡失败判定 |
| 肉鸽 | 至少 15 个强化，战后 3 选 1 |
| 养成 | 局内领主升级、建筑升级、少量局外永久解锁 |
| 流程 | 主菜单、开始、暂停、胜利、失败、重新开始 |
| 存档 | 设置、局外解锁、必要的游戏进度 |
| 工坊基础 | 数据驱动注册、本地内容包加载、内容校验 |

第一版领主只实现边境骑士。森林游侠和工程领主留作以后验证「新增领主不改核心逻辑」的样例，不在第一版里提前做完。

## 第一版不做

- 多人、PVP、排行榜
- 完整居民生活模拟和复杂职业 AI
- 无边界开放世界
- 装备词缀、宠物、坐骑
- 玩家自定义脚本、可视化模组编辑器、在线工坊
- 大量正式美术和过场动画

在线发布和订阅可以以后再做。内容加载和校验的边界从第一版就要成立。

## 第一版验收

第一版完成与否看下面 8 条，不看生成了多少脚本。

1. 能完成建设、探索、夜战、奖励结算和下一夜。
2. 不扩张可以完成基础难度；扩张能带来额外资源和开发空间。
3. 敌人寻路、攻击、死亡、墙体破坏和胜负判定正常。
4. 建造扣款、生产、升级和拆除没有明显资源漏洞。
5. 新增一个建筑或领主不需要修改与其无关的核心逻辑。
6. 加载示例内容包能新增一个领主或建筑，错误内容会被拒绝。
7. 重启后，局外解锁和约定需要保留的进度能够恢复。
8. Windows 导出包能够启动、开始游戏并完成一局。

阶段 0 不要求满足这 8 条。阶段 0 的验收见开发计划。
